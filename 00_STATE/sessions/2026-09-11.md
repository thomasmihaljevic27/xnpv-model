# Session 2026-09-11 - Scripted two-way GitHub sync for both machines

- [REQUEST] A PowerShell command that scans the repo folder for changes and pushes them, and pulls anything on GitHub that is not local. Follow-up request after a failed one-liner: two files, one per machine, that run the full re-sync automatically.
- [INCIDENT] The desktop was found in detached HEAD with an interactive rebase half-applied (`82f408e` picked onto `b4ef92b`, no commands remaining, working tree clean). Cause was a `git pull --rebase` that stopped partway and was never continued. Resolved by the user on the desktop; `origin/main` is at `420e367` and carries the work. No commits lost.
- [BUILT] `sync.ps1` at the repo root, plus `Sync-Desktop.cmd` and `Sync-Laptop.cmd` launchers, plus `.gitattributes` forcing CRLF on `.cmd` and `.ps1` so checkout on either Windows machine gets correct line endings.
- [DESIGN] One script, two launchers, rather than two duplicated scripts: `sync.ps1` locates the repo from `$PSScriptRoot`, so the differing Windows usernames (`Thomas` desktop, `thoma` laptop) need no per-machine edit and a fix is made once. The launchers carry the machine-specific absolute path so they can be pinned or copied to the Desktop, and fall back to their own folder when that path is wrong. The `.cmd` layer also supplies what a bare `.ps1` cannot: double-click execution, `-ExecutionPolicy Bypass` scoped to the one process, and a window that stays open.
- [DESIGN] Pull is `--no-rebase` by choice. Rebase caused the incident above by rewriting local commits and parking HEAD off the branch mid-operation; a merge pull always leaves the user on their branch. Guards abort the run when `rebase-merge`, `rebase-apply`, `MERGE_HEAD`, or `CHERRY_PICK_HEAD` is present, or when HEAD is detached. `$ErrorActionPreference` is deliberately left at default because git writes routine progress to stderr and `Stop` would kill the script on a successful command; exit codes are checked via `$LASTEXITCODE` instead. Push retries three times with widening delays for laptop wifi.
- [QA] Two self-inflicted bugs caught before shipping. PowerShell was binding `-A`, `-m`, `-u`, `--no-rebase` as parameter names of the `Invoke-Git` helper instead of passing them to git; fixed by taking a single positional `[string[]]` and calling with explicit arrays. `git rev-parse --git-dir` returns a path that is relative or absolute depending on context and `Join-Path` mangles the absolute case; switched to `--absolute-git-dir`.
- [QA] Parse-checked with the PowerShell 7.4.6 AST parser (no syntax errors), then executed end-to-end against a throwaway bare-repo pair. Six cases pass: normal commit-and-push; idempotent rerun with no changes; two-way sync where a remote commit is pulled and a local commit pushed in the same run; detached-HEAD guard; mid-rebase guard reproducing the exact desktop stall; and an add/add conflict, which stops cleanly, stays on the branch, and recovers with `git merge --abort`. Not tested against Windows PowerShell 5.1 or on either real machine; the script avoids 7-only syntax but the first real run is the confirmation.
